# Rebut 0.5.0

npm으로 설치한 Rebut을 같은 경로에서 업데이트할 수 있습니다. 명령별 도움말과 MCP 등록 점검을 추가했고, Windows에서 공급자 연결 오류를 확인하기 쉬워졌습니다.

## CLI

- `rebut update`는 현재 사용 중인 npm 전역 설치를 찾아, npm `latest`가 더 새로운 안정 버전이면 같은 경로에 설치합니다. `--prefix`로 별도 경로에 설치한 경우에도 해당 경로를 사용합니다. 그 경로에서 이미 업데이트가 진행 중이면 두 번째 설치를 막습니다. [#90](https://github.com/abruption/rebut/pull/90)
- `rebut help setup`이나 `rebut profile list --help`로 명령별 사용법을 볼 수 있습니다. 도움말을 볼 때는 설정 파일이나 로컬 데이터베이스를 열지 않습니다. [#92](https://github.com/abruption/rebut/pull/92)
- `rebut setup --check --client codex` 또는 `rebut setup --check --client claude`로 선택한 호스트 설정의 등록 누락, 끊어진 실행 경로, 다른 경로의 실행 파일을 가리키는 등록 등을 확인할 수 있습니다. 실제 연결 상태는 호스트에서 확인하세요. [#92](https://github.com/abruption/rebut/pull/92)

## Windows

- `rebut doctor --provider`에서 TLS 인증서 오류를 구분해 표시합니다. Windows 설정 오류에는 환경변수와 전용 데이터 경로를 안내합니다. 설치 안내에 사용자 npm 경로와 인증서 설정 방법을 추가했습니다. [#88](https://github.com/abruption/rebut/pull/88)
- Windows CI는 npm 패키지를 설치하고 로컬 MCP 프로세스를 새로 시작한 뒤 기존 요청 상태를 조회합니다. 실기기에서는 Codex와 Claude Code의 등록 점검을 확인했습니다. 공급자 연결은 모델 메타데이터 조회로, 리뷰 흐름은 모의 응답으로 확인했습니다. [#88](https://github.com/abruption/rebut/pull/88) · [#92](https://github.com/abruption/rebut/pull/92)
- Mac과 Windows에서 새 명령을 포함한 테스트용 0.4.0을 공개 0.4.1로 업데이트해, 두 기기 모두 처음 설치한 경로를 사용하는지 확인했습니다. [#90](https://github.com/abruption/rebut/pull/90)

## 업데이트

0.4.1에서 처음 올릴 때는 `npm install -g rebut-mcp@0.5.0`을 사용하세요. 기존 설치에 `--prefix`를 지정했다면 같은 경로를 지정합니다. 설치한 뒤 `rebut --version`으로 확인하고 MCP 호스트를 다시 시작하세요. 0.5.0부터는 `rebut update`로 다음 버전을 설치할 수 있습니다. [설치와 사용](../guide/ko/installation.md)
