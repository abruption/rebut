# Rebut 0.3.3

월간 예산 갱신일을 설정하는 기능을 추가하고 Worker 인증과 로컬 설정 파일 검사를 강화했습니다.

## 월간 예산

- `rebut budget`은 월간 예산 반영액과 한도, 다음 갱신 시각, 미해결 요청이 점유한 동시 실행 슬롯을 보여줍니다. Worker 모드에서는 관리자 토큰이 필요합니다. 표시 금액은 Rebut 장부 기준입니다. [#57](https://github.com/abruption/rebut/pull/57)
- 기본 갱신 시각은 매월 1일 00:00 UTC입니다. `rebut budget set-start-day DAY`는 1~28을 받습니다. 기본인 1일에서 2~28일 중 하나로 원장마다 한 번 전환할 수 있고, 이미 설정한 값을 다시 지정해도 설정은 바뀌지 않습니다. 빈 원장은 즉시 전환합니다. 요청 기록이 있는 원장은 현재 기간을 다음 달의 지정일까지 연장합니다. 예를 들어 11월에 15일을 선택하면 12월 15일 00:00 UTC에 처음 갱신합니다.
- 기존 요청의 비용은 원래 기간에 남습니다. `unknown` 요청이 보유한 예산 예약과 동시 실행 슬롯도 유지됩니다. 연결이 끊겼다면 같은 백엔드에서 원래 요청 ID의 상태를 조회하세요.

## 인증 및 설정

- Worker는 `AUTH_TOKENS`의 다이제스트가 인증 주체별로 고유한지 검사합니다. `ADMIN_TOKEN_SHA256`을 설정한다면 일반 인증 다이제스트와 겹치지 않아야 합니다. 값이 비어 있으면 관리자 토큰을 미설정으로 처리합니다. 잘못된 인증 설정은 보호되는 경로에서 요청을 거부합니다. [#62](https://github.com/abruption/rebut/pull/62)
- CLI는 `config.json`과 설정 디렉터리의 소유권을 확인합니다. 설정 파일은 현재 계정 소유의 일반 파일로 권한을 `0600`으로 설정하고, 설정 디렉터리도 현재 계정이 소유해야 합니다. 설정 디렉터리와 상위 경로는 다른 사용자가 쓸 수 없는 위치를 사용하세요. [#63](https://github.com/abruption/rebut/pull/63)

## 업그레이드

CLI 갱신 전에 설정 파일과 디렉터리의 소유권과 권한을 확인하세요. Worker를 배포하기 전에는 인증 다이제스트가 서로 겹치지 않는지 확인하세요.

- 로컬 모드에서는 CLI를 갱신하세요. 맞춤 갱신일을 설정하면 로컬 원장이 자동으로 업그레이드되므로, 이전 CLI 버전에서 해당 원장을 열 수 없습니다.
- Worker 모드에서는 CLI를 갱신하고 새 Worker 코드를 배포하세요. 맞춤 갱신일을 사용하려면 새 코드 배포 후 D1 마이그레이션 `0003_budget_cycle.sql`을 적용한 뒤 시작일을 설정하세요. 기본 달력월을 계속 쓰는 데는 이 마이그레이션이 필요하지 않습니다. 맞춤 갱신일을 적용한 뒤에는 이전 Worker에서 신규 예약을 할 수 없습니다. [한국어 설정 안내](../guide/ko/configuration.md)
