# Rebut 0.4.0

Codex와 Claude Code에서 두 프로필을 선택해 같은 변경을 병렬로 검토할 수 있습니다. 각 호스트의 단일 리뷰 기본 프로필도 따로 지정할 수 있습니다.

## 병렬 리뷰

- 두 건의 유료 리뷰를 명시적으로 선택했다면 `review_pair`를 사용합니다. 수집한 스키마 2 번들을 `first`로 넘기고, `second`에 두 번째 프로필, 공급자, 별도 요청 ID를 지정합니다. 두 리뷰는 같은 자료를 서로 독립적으로 검토합니다. [#69](https://github.com/abruption/rebut/pull/69)
- 예산이나 동시 실행 한도에 따라 한쪽만 접수될 수 있습니다. 두 요청이 모두 접수된 경우에도 한쪽 결과가 불확실하면 반환된 본문만 확인할 수 있습니다. 응답이 끊기면 같은 백엔드에서 두 요청의 원래 ID로 `review_status`를 조회합니다. 상태 조회로 리뷰 본문을 다시 받을 수 없습니다.
- 로컬 한도가 2 미만이면 두 요청을 보내기 전에 거부합니다. 기본 한도는 1입니다. 병렬 리뷰를 쓰려면 `rebut set max-concurrent 2`를 실행한 뒤 MCP 호스트를 다시 시작합니다. 로컬에서 서로 다른 공급자를 쓰려면 Rebut 프로세스에 두 키가 필요하며, 환경변수 방식 등록은 기본적으로 선호 공급자의 변수만 전달합니다.

## 호스트별 단일 리뷰 기본값

```sh
rebut set profile claude-medium --client codex
rebut set profile astra-medium --client claude
```

`rebut collect --client codex` 또는 `--client claude`로 해당 기본값을 사용합니다. 명시적으로 전달한 `--profile`이 우선하며, 호스트를 지정하지 않으면 공통 기본값을 사용합니다. 지정된 호스트의 기본 프로필을 사용할 수 없으면 수집에 실패합니다. 기존 번들의 프로필과 공급자는 유지됩니다. [#71](https://github.com/abruption/rebut/pull/71)

CLI를 갱신한 후 기존 등록은 `rebut setup --client codex --replace` 또는 `rebut setup --client claude --replace`로 갱신하고 호스트를 다시 시작합니다. Worker 모드에서도 두 기능은 CLI에서 동작하므로 새 기능을 쓰기 위한 Worker 재배포나 D1 마이그레이션은 필요하지 않습니다. 구버전으로 되돌리려면 0.4.0에서 `rebut set profile --client codex --clear`와 `rebut set profile --client claude --clear`를 실행하고, 이전 CLI를 설치한 뒤 두 호스트를 다시 등록합니다. [한국어 설정 안내](../guide/ko/configuration.md)

## npm 발행 검증

npm 게시 후 공개 파일이 잠시 다운로드되지 않으면 검증 단계가 최대 25회, 전체 7분 이내로 재시도합니다. 파일 해시가 다르거나 영구 오류가 발생하면 즉시 실패합니다. [#67](https://github.com/abruption/rebut/pull/67)
