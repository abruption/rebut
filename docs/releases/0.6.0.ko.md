# Rebut 0.6.0

`rebut update`로 기존 Codex와 Claude Code 등록을 npx 실행 방식으로 전환할 수 있습니다. 수락 기준별 근거를 담은 출력을 선택할 수 있고, 자동화에서는 완료 본문을 받았는지 종료 코드로 확인할 수 있습니다.

## MCP 실행 방식 전환

- `rebut update`는 패키지 확인에 성공하면 전환 가능한 기존 Codex와 Claude Code 등록을 바꿔 `rebut-mcp@latest`를 npx로 실행합니다. CLI가 이미 최신이어도 등록을 확인합니다. 도구 승인과 자격증명 전달 설정은 보존합니다. [#100](https://github.com/abruption/rebut/pull/100)
- Windows의 Claude Code는 업데이트에 사용한 Node 설치본의 `npx-cli.js`를 절대 경로로 실행합니다. Node 설치 위치가 바뀌면 `rebut update`로 등록을 갱신하세요. [#100](https://github.com/abruption/rebut/pull/100)

## 검토 결과와 요청 복구

- `rebut collect`에 `--criterion-id ID`를 하나 이상 지정하면 확장 출력 v2를 선택합니다. 같은 명령에 `--output-schema 2`를 추가해 출력 형식을 명시할 수도 있습니다. v2는 기준별 평가와 인용, 재현 제안을 담습니다. 기준 ID와 인용 범위를 검사하고, 응답에서 빠진 기준은 `unassessed`로 표시합니다. 기본 출력은 기존 형식입니다. 재현 제안과 기준 충족 여부는 검토 자료와 대조하세요. [#96](https://github.com/abruption/rebut/pull/96)
- `rebut review --strict-exit`은 입력 해시와 요청한 형식에 맞는 완료 본문을 받은 경우에만 종료 코드 0을 반환합니다. 완료 메타데이터만 받거나 MCP 오류가 발생하면 0이 아닌 코드로 종료합니다. 표준 출력의 JSON 형식은 유지됩니다. [#98](https://github.com/abruption/rebut/pull/98)
- 요청 ID를 잃었다면 `rebut status --pending`으로 예약(`reserved`)·미확인(`unknown`) 상태의 요청을 찾아볼 수 있습니다. 0.6.0 Worker에서는 현재 인증 주체의 요청을 최대 100건 표시하고, 목록에 더 있는지는 `has_more`로 확인할 수 있습니다. 원래 ID 조회와 대기 상태 조회는 모델 호출 없이 처리합니다. [#98](https://github.com/abruption/rebut/pull/98)

## 업데이트

0.5.0에서 올릴 때는 `rebut update`로 새 CLI를 설치한 다음 같은 명령을 다시 실행해 MCP 등록을 전환하세요. 이전 업데이터가 npm 12의 버전 응답을 읽지 못하면 `npm install -g rebut-mcp@0.6.0`으로 먼저 설치한 뒤 `rebut update`를 실행하세요. 따로 지정한 `--prefix`가 있다면 기존 설치 경로를 사용하세요. 전환 뒤 Codex나 Claude Code를 다시 시작해 Rebut 도구를 확인하세요. [설치와 사용](../guide/ko/installation.md)

Worker에서 확장 출력 v2나 `status --pending`을 쓰려면 Worker도 0.6.0으로 올리세요. 0.5.0 Worker를 계속 이용하는 경우 기본 출력이나 `--output-schema 1`을 사용하고, 원래 요청 ID로 상태를 조회하세요. 0.5.0 Worker에서 올릴 때는 기존 D1과 인증 주체를 유지한 채 Worker 코드만 갱신하세요. [입력·결과 계약](../guide/ko/configuration.md) · [운영](../guide/ko/operations.md)
