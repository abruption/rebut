## unknown 结果诊断

新处理的 `unknown` 结果包含固定白名单中的 `unknown_reason` 和 `provider_elapsed_ms`，用于区分超时、传输或正文读取错误、大小／JSON／编码限制以及模型或用量不匹配。不会保留异常字符串或响应正文。正文处理失败时，已收到的安全供应商请求 ID 和 HTTP 错误状态仍会保留。耗时仅是应用的观测值，不证明供应商执行或计费完成。历史记录中缺失的元数据无法追溯恢复。unknown 的预算预留和并发槽继续保留；新增诊断不会延长超时、重试请求或释放预留。

`unknown_reason` 表示处理停止的位置。若同时存在 `upstream_status`，可能已观测到 HTTP 错误，随后在等待正文时超时。应结合两个字段解释。历史记录和防御性错误路径可能没有诊断字段。

在获准的付费对照中，旧 45 秒期限下结束的输入，在隔离的 30 分钟期限版本中约 195 秒后完成，供应商响应头约 194 秒后到达。这说明该输入的旧期限不足，并不保证所有审查的耗时。需同时应用供应商 1,800 秒、MCP 客户端 1,830 秒和 Codex 1,860 秒的期限。unknown 预算预留和去重策略保持不变。
