# 明示的に選択する独立レビュー

[한국어](../ko/reviewer-integration.md) · [English](../en/reviewer-integration.md) · [简体中文](../zh-CN/reviewer-integration.md) · **日本語**

[Rebut](../../../README.ja.md) · [ユーザーガイド](../ja.md)

既存のレビュアーの既定方針を維持してください。ユーザーが OpenAI API レビュアーを明示的に要求した場合にだけ Rebut を選びます。Rebut を選択しただけでは Claude/Gemini 呼び出しは許可されず、このアダプターが存在しても、3 つのレビュアーへの同時振り分けを意味しません。

1. 必要な証拠だけを収集し、シークレットを除去し、内容を確認して確定し、正規化した SHA-256 を記録します。独立したレビュアーには同じ証拠を渡し、それぞれの出力を分けて保持します。独立した初回レビューには、別のレビュアーの出力や主エージェントの途中段階の結論を含めないでください。
2. サーバーの許可リスト内のプロファイルを選びます。付属の設定例は Astra/medium を使用します。意図して新しいレビューを行う場合は新しいリクエスト ID を設定し、タイムアウトや不確かなレスポンスの後は同じ ID を保持してください。
3. JSON バンドルを標準入力で渡し、非公開の `REBUT_ENDPOINT` / `REBUT_TOKEN` 環境変数を設定して、`npm run client -- review` を使用します。レスポンスはアクセス権限を制限してローカルに保存してください。Bearer 値をコマンドや追跡対象の設定に入れないでください。
4. 既存の Vaultwarden ワークフローでは、`REBUT_ENDPOINT=https://YOUR_HOST/mcp python3 scripts/bw-client.py review < /protected/request.bundle.json` が、指定名のトークンを `bw-get` で読み込み、メモリ内でのみクライアントに渡します。パスワードマネージャーの既定の項目名は `Rebut — MCP Access Token` です。必要に応じて `REBUT_BW_ITEM` で名前を上書きします。OpenAI キーはクライアントに渡しません。`list` と `status REQUEST_ID` は有料レビューを実行しません。
5. ステータスが `completed` であること、モデル・プロファイル・ハッシュが想定どおりであること、指摘と使用量が有効であることを確認します。指摘が空でも正しさの証明にはなりません。指摘された各不具合を元のソースと照らし合わせてください。実際のモデル、入力ハッシュ、使用量、推定費用、制限を報告します。スキーマへの準拠だけでは、指摘の真偽を検証したことにはなりません。
6. 失敗またはタイムアウトしたリクエストには `status REQUEST_ID` を使い、新しい ID で自動再試行しないでください。`unknown`/`reserved` は課金済みの実行を意味する場合があり、予約を保持します。完了済みの重複リクエストはメタデータだけを返します。最初のレスポンスをローカルに保持してください。

この API アダプターは Codex CLI とは別のもので、レビュアーにツール、リポジトリアクセス、シェル実行、コード変更、公開の権限を与えません。互換性を主張できるのは、そのデプロイでテスト済みのクライアントとデバイスだけです。ブラウザープロファイルや認証情報をコピーせず、追加するホストごとに個別に検証してください。
