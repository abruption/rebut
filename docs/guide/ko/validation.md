## unknown 진단

새로 처리한 `unknown` 결과에는 고정된 `unknown_reason` 코드와 `provider_elapsed_ms`가 포함됩니다. 시간 초과, 전송·응답 읽기 오류, 크기·JSON·인코딩 제한, 모델·사용량 불일치 등을 구분하며 예외 문자열이나 응답 본문은 저장하지 않습니다. 본문 처리에 실패해도 이미 수신한 안전한 공급자 요청 ID와 HTTP 오류 상태는 유지합니다. 경과 시간은 애플리케이션의 관측값이며 공급자의 실행·청구 완료 증거가 아닙니다. 기존 기록의 누락 정보를 소급 복구하지 않으며, unknown의 예약과 동시성 슬롯은 계속 유지됩니다. 이 진단 추가는 시간 제한 변경이나 자동 재시도·예약 해제를 의미하지 않습니다.

`unknown_reason`은 처리가 중단된 지점을 설명합니다. `upstream_status`가 함께 있으면 HTTP 오류 상태를 이미 관측한 뒤 본문 대기 중 시간 제한에 도달했을 수 있습니다. 두 필드는 함께 해석하며, 진단 필드가 없는 과거 기록이나 방어적 오류 경로도 허용합니다.

실제 유료 대조에서는 기존 45초 제한에서 종료된 입력이 30분 한도의 격리 진단 버전에서 약 195초 뒤 완료됐고, 공급자 헤더는 약 194초 뒤 도착했습니다. 이 결과는 해당 입력에서 기존 한도가 부족함을 보여주며 모든 리뷰의 실행 시간을 보장하지 않습니다. 공급자 1,800초·MCP 클라이언트 1,830초·Codex 1,860초를 함께 적용합니다. unknown의 예산 예약과 중복 방지 정책은 유지됩니다.
